# Xbox Series X Controller Trigger Rumble on Linux

A detailed setup and troubleshooting guide for using an **Xbox Series X|S Wireless Controller on Linux** with **xpadneo**, including trigger vibration/rumble and Steam Input compatibility.

Tested configuration:

* **OS:** CachyOS
* **Kernel:** `7.2.4-3-cachyos`
* **Kernel headers:** `linux-cachyos-headers 7.2.4-3`
* **Controller:** Xbox Wireless Controller / Xbox Series X|S
* **Connection:** Bluetooth
* **Driver:** xpadneo
* **Steam:** Steam Input enabled
* **Game:** Forza Horizon 4
* **Controller Bluetooth address:** Do not document personal device addresses in public repositories

---

## 1. Overview

Xbox Series X|S controllers use Bluetooth HID/HOGP when connected wirelessly to Linux.

The standard Linux `hid-generic` driver can detect the controller, but it does not provide the level of Xbox-specific functionality required for proper rumble and trigger feedback.

**xpadneo** is a Linux kernel driver specifically designed for Xbox One S and newer Xbox-compatible controllers over Bluetooth.

The resulting architecture is:

```text
Xbox Series X|S Controller
          │
          │ Bluetooth / BLE
          ▼
      HOGP / HID
          │
          ▼
       xpadneo
          │
          ▼
 Linux input / force feedback
          │
          ▼
      Steam Input
          │
          ▼
   Game / Proton / Wine
```

For games that do not properly recognize the controller directly under Linux, Steam Input can provide an Xbox-compatible controller interface.

---

# 2. Why xpadneo?

Without xpadneo, the controller may appear in the kernel as:

```text
hid-generic
```

For example:

```text
hid-generic 0005:045E:0B13.000C:
input,hidraw11: BLUETOOTH HID v5.23 Gamepad
[Xbox Wireless Controller]
```

This means Linux can see the controller, but the Xbox-specific driver is not handling it.

After installing xpadneo, the controller should instead appear in the kernel log with entries such as:

```text
xpadneo ... gamepad detected
xpadneo ... Xbox Wireless Controller ... connected
xpadneo ... rumble streaming enabled
```

# 4. Installing xpadneo

Clone the upstream repository:

```bash
git clone https://github.com/atar-axis/xpadneo.git ~/xpadneo
```

Enter the repository:

```bash
cd ~/xpadneo
```

Run the installer:

```bash
sudo ./install.sh
```

The driver is installed through DKMS.

---

# 5. Verify the installation

Check whether the kernel module exists:

```bash
modinfo hid_xpadneo
```

A successful installation should show something similar to:

```text
filename: /lib/modules/7.2.4-3-cachyos/updates/dkms/hid-xpadneo.ko.zst
license: GPL
description: Linux kernel driver for Xbox ONE S+ gamepads (Bluetooth), including rumble
version: v0.11-pre-64-g9aa168e
name: hid_xpadneo
```

Check whether the module is loaded:

```bash
lsmod | grep hid_xpadneo
```

Expected:

```text
hid_xpadneo
```

If `modinfo` reports:

```text
Module hid_xpadneo not found
```

then xpadneo has not been successfully installed for the currently running kernel.

# 6. Pairing the Xbox Controller

Start Bluetooth:

```bash
bluetoothctl
```

Inside `bluetoothctl`:

```text
power on
agent on
default-agent
scan on
```

Put the Xbox controller into pairing mode.

It should appear as:

```text
Xbox Wireless Controller
```

Pair it:

```text
pair XX:XX:XX:XX:XX:XX
```

Trust it:

```text
trust XX:XX:XX:XX:XX:XX
```

Connect it:

```text
connect XX:XX:XX:XX:XX:XX
```

Verify:

```bash
bluetoothctl devices
```

# 7. Verify xpadneo is handling the controller

Check the kernel log:

```bash
sudo dmesg | grep -iE 'xpadneo|xbox|hid' | tail -50
```

A correctly functioning controller should produce messages similar to:

```text
xpadneo ... share button detected
xpadneo ... gamepad detected
xpadneo ... enabling compliance with Linux Gamepad Specification
xpadneo ... Xbox Wireless Controller ... connected
xpadneo rumble_welcome start
xpadneo ... testing weak motor
xpadneo ... testing strong motor
xpadneo ... testing trigger motors
xpadneo rumble_welcome took ...
xpadneo ... rumble streaming enabled
```

The most important lines are:

```text
testing trigger motors
```

and:

```text
rumble streaming enabled
```

These indicate that xpadneo detected the controller's rumble hardware and attempted to test the trigger motors.

# 8. Controller identification

An Xbox Series X|S controller may initially identify itself with a device ID such as:

```text
VID: 045E
PID: 0B13
```

xpadneo may then present the controller as an Xbox-compatible device.

For example, the kernel can report:

```text
pretending XB1S Windows wireless mode
(changed VID from 0x045E to 0x045E,
PID from 0x0B13 to 0x028E)
```

This is intentional.

`0x028E` is associated with an Xbox 360 controller.

Therefore Steam may display:

```text
Xbox 360 Controller
```

even though the physical controller is an Xbox Series X|S controller.

This does **not** mean that the wrong controller has been connected.

It is an xpadneo compatibility mechanism intended to make existing Linux games and APIs recognize the controller.

# 9. Trigger rumble configuration

xpadneo exposes its configuration through:

```text
/sys/module/hid_xpadneo/parameters/
```

List the available parameters:

```bash
ls /sys/module/hid_xpadneo/parameters/
```

Relevant parameters include:

```text
rumble_attenuation
trigger_rumble_mode
ff_connect_notify
force_disable_hogp
```

---

## 9.1 Rumble attenuation

Check the current configuration:

```bash
cat /sys/module/hid_xpadneo/parameters/rumble_attenuation
```

Recommended starting configuration:

```text
0,0
```

This means no attenuation is applied.

The configuration is:

```text
rumble_attenuation=0,0
```

This allows maximum rumble strength rather than intentionally reducing it.

---

## 9.2 Trigger rumble mode

Check:

```bash
cat /sys/module/hid_xpadneo/parameters/trigger_rumble_mode
```

The current configuration used in this setup is:

```text
1
```

Do not change this immediately if trigger rumble is already working.

Different modes can produce different trigger-feedback behavior depending on the controller, Bluetooth mode, and software generating the force-feedback effect.

---

# 10. Temporarily changing trigger rumble mode

A parameter can be changed at runtime for testing.

For example:

```bash
echo 0 | sudo tee /sys/module/hid_xpadneo/parameters/trigger_rumble_mode
```

Then reconnect the controller and test the game.

To restore the previous value:

```bash
echo 1 | sudo tee /sys/module/hid_xpadneo/parameters/trigger_rumble_mode
```

These changes are temporary and normally disappear after reboot/module reload.

Do not make changes permanent until the desired behavior has been verified.

# 11. Steam Input

Some Linux games do not correctly recognize Xbox Series controllers when xpadneo presents them through the Linux input subsystem.

Steam Input can solve this.

For games that require Steam Input:

```text
Steam
  → Library
  → Game
  → Properties
  → Controller
  → Enable Steam Input
```

Steam may then identify the controller as:

```text
Xbox 360 Controller
```

This is expected when xpadneo is using its Xbox-compatible presentation.

---

# 12. Forza Horizon 4

Forza Horizon 4 can be problematic with direct controller input on Linux.

In this setup, Steam Input is required because the game does not properly accept the controller through the direct input path.

Recommended configuration:

```text
Steam Input: Enabled
xpadneo: Enabled
Bluetooth: Enabled
```

The resulting input path becomes:

```text
Xbox Series X Controller
        ↓
Bluetooth HOGP
        ↓
xpadneo
        ↓
Xbox-compatible controller
        ↓
Steam Input
        ↓
Forza Horizon 4
```

# 13. Why Steam calls it an Xbox 360 controller

This is one of the most confusing parts of the setup.

The physical controller is:

```text
Xbox Series X|S Controller
```

but xpadneo can intentionally change the reported identity:

```text
Xbox Series Controller
        ↓
xpadneo compatibility layer
        ↓
Xbox 360-compatible identity
        ↓
Steam
```

Therefore Steam may display:

```text
Xbox 360 Controller
```

This is not a hardware downgrade or controller replacement.

It is simply the device identity exposed to userspace.

# 14. Trigger vibration vs normal rumble

Xbox Series X|S controllers have separate vibration hardware in the triggers.

There are therefore two different types of feedback:

### Standard rumble

Generated by the conventional vibration motors:

```text
Left motor
Right motor
```

### Trigger rumble

Generated by the trigger motors:

```text
Left trigger motor
Right trigger motor
```

xpadneo can detect and test the trigger motors separately.

The following log is therefore significant:

```text
testing weak motor
testing strong motor
testing trigger motors
```

If the normal rumble works but the trigger vibration does not, the problem is likely further up the software stack.

---

# 15. HOGP / BLE

The controller may be connected using:

```text
HOGP
```

which means:

```text
HID over GATT Profile
```

This is the Bluetooth Low Energy HID transport used by many modern controllers.

xpadneo may report:

```text
expecting HOGP protocol
```

and:

```text
uses_hogp 1
```

This indicates that the controller is using the BLE/HOGP path.

The driver can also warn that HOGP can cause rumble compatibility problems for controllers that do not actually use BLE.

For a modern Xbox Series controller, HOGP/BLE is expected.

---

# 16. Rumble test performed by xpadneo

When the controller connects, xpadneo may automatically perform a rumble test.

Typical sequence:

```text
rumble_welcome start
```

Then:

```text
testing weak motor
```

Then:

```text
testing strong motor
```

Then:

```text
testing trigger motors
```

Finally:

```text
rumble streaming enabled
```

If the controller physically vibrates during these tests, the kernel driver is communicating with the controller's force-feedback hardware.

# 17. Troubleshooting

## Controller detected but no xpadneo

Check:

```bash
lsmod | grep hid_xpadneo
```

If nothing is returned:

```bash
sudo modprobe hid_xpadneo
```

Then reconnect the controller.

---

## Module not found

Run:

```bash
modinfo hid_xpadneo
```

If it says:

```text
Module hid_xpadneo not found
```

check:

```bash
uname -r
```

and:

```bash
pacman -Qs linux-headers
```

The installed xpadneo DKMS module must be built for the running kernel.

Reinstall:

```bash
cd ~/xpadneo
sudo ./install.sh
```

---

## Controller uses hid-generic

Check:

```bash
sudo dmesg | grep -iE 'xpadneo|hid-generic|xbox' | tail -50
```

If you only see:

```text
hid-generic ... Xbox Wireless Controller
```

xpadneo has not taken over the device.

Check that the module is installed and loaded:

```bash
modinfo hid_xpadneo
lsmod | grep hid_xpadneo
```

Then disconnect and reconnect the controller.

---

## Normal rumble works but trigger rumble does not

Check:

```bash
cat /sys/module/hid_xpadneo/parameters/trigger_rumble_mode
```

Then inspect:

```bash
sudo dmesg | grep -iE 'trigger|rumble|xpadneo' | tail -50
```

Look for:

```text
testing trigger motors
```

If this appears, xpadneo is detecting the trigger motors.

The remaining problem may be the software sending the force-feedback effect.

---

# 18. Steam Input accuracy issues

Steam Input introduces another translation layer.

For example:

```text
Game
 ↓
Steam Input
 ↓
Xbox-compatible controller
 ↓
xpadneo
 ↓
Bluetooth
 ↓
Xbox controller
```

Trigger effects may therefore not be identical to the native Xbox Series X implementation.

If trigger vibration works but feels:

* weaker
* delayed
* too strong
* less granular
* different from Windows/Xbox

the issue may not be xpadneo itself.

Steam Input may be translating the force-feedback effects into a format appropriate for the Xbox 360-compatible device exposed by xpadneo.

This is especially relevant for games that do not natively understand the Xbox Series controller.
